# Business Questions

## Контекст

Аналіз продажів маркетплейсу Olist (Бразилія, 2016–2018).
Роль: аналітик інтернет-магазину. Мета: зрозуміти, що формує revenue, і підготувати dashboard для менеджменту.

**Датасет:** [Brazilian E-Commerce Public Dataset by Olist](https://www.kaggle.com/datasets/olistbr/brazilian-ecommerce)

---

## Визначення метрик

> Ці визначення фіксуються один раз і використовуються в SQL, Python і Power BI однаково.

| Метрика | Визначення |
|---|---|
| **Revenue** | Сума `price` з `order_items` (без `freight_value`) |
| **Замовлення в розрахунках** | Лише `order_status = 'delivered'` |
| **Клієнт** | Унікальний `customer_unique_id` (не `customer_id`, бо він унікальний для кожного замовлення) |
| **Активний клієнт** | Клієнт із хоча б одним замовленням у вибраному періоді |
| **AOV** | Revenue / кількість унікальних замовлень (рахується по замовленнях, а не по рядках `order_items`) |
| **Повторний клієнт** | Клієнт із 2 і більше замовленнями |
| **Регіон** | `customer_state` (штат клієнта) |
| **Місяць замовлення** | Місяць з `order_purchase_timestamp` |
| **Аналізований період** | _Заповнити після перегляду даних: виключити неповні місяці на краях датасету_ |

---

## Обмеження датасету

- Немає даних про собівартість, тому аналізується **revenue, а не прибуток**.
- Період охоплює менше двох повних років, тому висновки про сезонність обмежені.
- Крайні місяці датасету неповні (кінець 2016 і кінець 2018).
- Повторних покупок мало, що є особливістю даних, а не помилкою.
- _Доповнювати по ходу data cleaning та EDA._

## Питання

### Revenue та динаміка

**1. Який загальний revenue?**
- Навіщо: базовий KPI для менеджменту.
- Метрика: сума `price` для delivered-замовлень.
- Таблиці: `orders`, `order_items`.
- Відповідь: SQL, KPI-картка в Power BI.

**2. Як revenue змінювався по місяцях?**
- Навіщо: побачити тренд і темпи зростання.
- Метрика: revenue по місяцях; MoM growth через `LAG()`.
- Нюанс: неповні місяці на краях виключити або позначити.
- Таблиці: `orders`, `order_items`.
- Відповідь: SQL, Python, Power BI.

### Продукти

**3. Які категорії генерують найбільше revenue?**
- Навіщо: зрозуміти, на яких категоріях тримається бізнес.
- Метрика: revenue по категоріях та їхня частка від загального.
- Нюанс: назви категорій португальською, потрібна таблиця перекладу; окремо обробити товари без категорії.
- Таблиці: `order_items`, `products`, `product_category_name_translation`.
- Відповідь: SQL, Python, Power BI.

**4. Які товари приносять найбільше revenue?**
- Навіщо: визначити ключові товари.
- Примітка: питання «які товари найприбутковіші» неможливо розкрити повністю, бо немає собівартості. Аналізуємо revenue.
- Таблиці: `order_items`, `products`.
- Відповідь: SQL (`RANK()`), Python, Power BI.

### Клієнти

**5. Скільки активних клієнтів?**
- Метрика: `COUNT(DISTINCT customer_unique_id)`, загалом і по місяцях.
- Таблиці: `orders`, `customers`.
- Відповідь: SQL, Power BI.

**6. Який Average Order Value (AOV)?**
- Метрика: revenue / унікальні замовлення.
- Нюанс: рахувати по замовленнях, інакше `JOIN` з `order_items` дає хибний результат.
- Таблиці: `orders`, `order_items`.
- Відповідь: SQL, Python (розподіл вартості замовлення), Power BI.

**7. Скільки клієнтів роблять повторні покупки?**
- Метрика: частка клієнтів із 2+ замовленнями.
- Нюанс: очікується мала частка; це висновок, а не проблема з даними.
- Таблиці: `orders`, `customers`.
- Відповідь: SQL (CTE), Power BI.

### Географія

**8. Які регіони приносять найбільше revenue?**
- Метрика: revenue, замовлення та клієнти по `customer_state`.
- Таблиці: `orders`, `order_items`, `customers`.
- Відповідь: SQL, Python, Power BI (карта).

### Сезонність

**9. Які місяці мають найбільше замовлень?**
- Метрика: кількість унікальних замовлень по місяцях.
- Таблиці: `orders`.
- Відповідь: SQL, Python.

**10. Чи є сезонність?**
- Метрика: порівняння однакових місяців різних років.
- Нюанс: даних менше двох повних років, тому формулюємо обережно («спостерігається пік у місяці X»), а не «сезонність доведена». Причини піків без підтвердження даними не вигадуємо.
- Таблиці: `orders`, `order_items`.
- Відповідь: Python, Power BI.

### Логістика та задоволеність _(специфічні для Olist)_

**11. Скільки часу займає доставка і як це залежить від регіону?**
- Метрика: `order_delivered_customer_date − order_purchase_timestamp` у днях, у розрізі `customer_state`.
- Нюанс: у датах бувають пропуски й аномалії (наприклад, доставка раніше за покупку), тому це частина data cleaning.
- Таблиці: `orders`, `customers`.
- Відповідь: SQL, Python, Power BI.

**12. Чи пов'язані затримки доставки з оцінками клієнтів?**
- Метрика: затримка = `order_delivered_customer_date > order_estimated_delivery_date`; порівняти середній `review_score` замовлень із затримкою та без.
- Нюанси: в одного замовлення може бути кілька відгуків, тому перед `JOIN` їх треба агрегувати; це кореляція, а не доказ причинності.
- Таблиці: `orders`, `order_reviews`.
- Відповідь: SQL, Python.

### Оплата _(специфічне для Olist)_

**13. Які способи оплати використовують клієнти і яка частка замовлень іде в розстрочку?**
- Метрика: розподіл `payment_type` та `payment_installments`, зв'язок із розміром замовлення.
- Нюанс: одне замовлення може мати кілька рядків оплати, тому `JOIN` з `order_items` легко задвоїти revenue.
- Таблиці: `order_payments`, `orders`.
- Відповідь: SQL, Python.
